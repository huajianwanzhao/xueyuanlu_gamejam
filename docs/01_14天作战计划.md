# 14 天作战计划（单人程序 + 2 策划 + 1 美术）

> 把 D1 换成你们的开赛日。默认你每天能投 3 小时，考试周降到 0.5 小时。

## 现实前提

- 14 天 ≠ 14 天工时。扣掉期中考试、数竞备考，你实际写代码约 **30–40 小时**。
- 这点时间只够：**一个机制 + 3~5 个关卡 + 菜单 + 打磨**。多一个系统就会烂尾。
- 你是单点故障：代码只有你会写，打包只有你会做。所以**早出包、勤提交**比写得快更重要。

## 日程表

|---|---|---|---|
| D1 | 跑通本模板，改一改看效果；建 git 仓库 | 讨论 3 个玩法方向 | 收集参考图 |

## 考试周降速预案（关键）

考前 2–3 天进入「最低维护模式」：

- 每天只花 **20–30 分钟**：`git pull` → 合并 → 出一次包 → `git push`。
- 提前派活：美术出最终图/UI；策划摆关卡、写文案、做测试记录。
- 回来时项目是**可运行**的，不是一堆半成品。

## 三条铁律

1. **D7 之前必须出过包**。打包问题（中文字体、音频、路径大小写）永远在最后一天爆炸。
2. **D11 功能冻结**。之后策划提新想法，统一回答「记下来，下一届做」。
3. **每天 push**。你电脑挂了 = 全队归零。

## 每周检查

- 现在能从头玩到尾吗？（不能就先修通，不加内容）
- 有没有哪个功能只有你能演示、别人跑不起来？（有就删）
- 距离截止还有几天，还剩几个功能？（功能数 > 剩余天数 ÷ 2 就砍）
