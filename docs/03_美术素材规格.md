## 1. 这些数字是怎么来的（你要懂，才能跟他解释）

不要一上来就报数字，先讲清推导链条。所有尺寸都从**一个**数长出来：

```
屏幕 640 × 360
   └─ 角色应该占屏幕多高？  → 28px（≈ 1/12.8 屏高）
        └─ 角色多宽？        → 16px（1 个 tile）
             └─ 其他物件？   → 按角色反推（见第 2 节）
```

**为什么角色占 1/13 屏高，而不是更大？**

平台跳跃游戏里，玩家要同时看清「我在哪」和「我要跳到哪」。角色越大，视野越窄，你做的关卡就得越小，玩起来越挤。参考：

- 《蔚蓝》Celeste：320×180 屏幕，角色约 8×11 像素 —— 比 1/13 还小
- 红白机《超级马里奥》：256×240 屏幕，小马里奥 16×16
- 反过来，1/5 屏高是**特写镜头**的尺度（《空洞骑士》那种偏写实、镜头跟随很近的），适合剧情演出，不适合要在一屏内判断跳跃的玩法

**为什么是 16 的倍数？**

屏幕上 640÷16 = 40 列、360÷16 = 22.5 行。所有东西对齐 16 网格，摆放时不会出现「差 1 像素」的缝，也不会出现像素画最忌讳的**半像素抖动**。

**为什么角色高是 28 不是 32？**

32 正好两格，画出来方方正正像积木；28 留了 4 像素给头顶的帽子/头发/动画起伏，跑动时头不会顶出格子。

**为什么素材尺寸必须和碰撞盒对上？**

程序里角色碰撞盒就是 **16 × 28**。美术如果把角色画成 20 宽，游戏里就会出现「看起来穿进墙里」或者「明明没碰到也被撞」——这是新手项目最常见的观感 bug。**图可以比碰撞盒小，但不能比它大。**

## 2. 尺寸表（发给美术的那张）

| 素材 | 尺寸（px） | 说明 |
|---|---|---|
| 角色 | **16 × 28** | 脚底对齐画布底边；只画面朝右，左向由程序翻转 |
| 金币 / 收集物 | **16 × 16** | 居中画，四周留 1–2px 空白 |
| 平台 / 地块 | **16 × 16** | 可平铺方块，长度在引擎里拉伸，不用画长条 |
| 终点 / 传送门 | **24 × 48** | 比角色高，是「目标物」的体量 |
| 背景 | **640 × 360** | 铺满整个屏幕，可分 2–3 层做视差 |
| UI 图标 | 16 / 24 / 32 | 一套里只用一种尺寸 |
| 标题 Logo | 宽 ≤ 480 | 高 ≤ 120 |

**画布**：640 × 360（16:9）。所有素材按 **1 像素 = 1 游戏像素** 画，透明背景用带 alpha 的 PNG。

---

## 3. 三条硬规则（像素画专属，违反了必翻车）

1. **不要画大图再缩小。** 按 1920 宽画完缩到 640，边缘一定是糊的、颜色是脏的。直接在 16×28 的画布上画。
2. **不要抗锯齿、不要半透明边缘。** 每个像素要么不透明要么全透明。半透明边缘会在游戏里变成一圈黑边（引擎的 alpha 处理导致）。
3. **不要旋转、不要非整数缩放。** 像素画一转就糊。需要斜向的物件，直接画斜的。

程序侧对应设置（已经配好，不用动）：纹理过滤 = Nearest，拉伸模式 = canvas_items。

## 4. 验收：30 秒判断这张图能不能用

1. 打开 Godot，双击 `scenes/dev/art_check.tscn`，按 **F6**。
2. 把美术给的 PNG 拖到 `Real` 节点的 **Texture** 上（`Zoom` 节点也拖同一张）。
3. 看三件事：
   - **Real（1:1）**：在这个尺寸下，角色还能看清脸/朝向/动作吗？看不清就是尺寸太小或细节太碎。
   - **Zoom（4 倍）**：每个小方格是否干干净净填满一个颜色？有杂色、有渐变、有半透明就是画法不对。
   - **和左边的橙色参考框对齐吗**：框是 16×28 的标准角色。你的图比它大 = 穿模风险。

## 6. 命名与目录

```
assets/sprites/player/idle_01.png, run_01.png, jump_01.png
assets/sprites/objects/coin.png, spike.png
assets/sprites/tiles/ground.png
assets/sprites/ui/button.png
assets/audio/sfx/coin.wav, jump.wav, die.wav, win.wav
assets/audio/music/bgm.ogg
```

- 全小写，下划线，不要中文名，不要空格。
- 动画帧用 `_01 _02 _03` 结尾，程序好批量导入。

## 7. 音频

- 音效：**wav**，16bit，44.1kHz，单声道，≤ 1 秒，音量归一化到 -3dB。
- 音乐：**ogg**，循环点做好，≤ 2 分钟。
- 文件名 = 代码里的名字（`coin.wav` → `AudioManager.play_sfx("coin")`）。

## 8.5 替换素材时，代码不用改（已经接好了）

美术的图到了之后，你唯一的动作是在编辑器里建一个资源，不碰任何脚本：

1. 把 `idle_01.png` `run_01.png` `run_02.png` `jump_01.png` 放进 `assets/sprites/player/`。
2. 在 Godot 里选中这些 png → 右键 → **新建 SpriteFrames** → 存成 `assets/sprites/player/player_frames.tres`。
3. 把动画名改成 `idle` `run` `jump`（可选 `die`），帧率设 8–12。

文件一存在，`player.gd` 会自动切过去（`_setup_visual()` 里判断 `FRAMES_PATH`），左右的翻转、跑/跳/待机的切换都已经写好了。**文件不在就继续用纯色块，不会报错。**

缺哪个动画就跳过哪个，只做了 `idle` 也能跑——所以美术可以先交一个动作，不用等全套。
